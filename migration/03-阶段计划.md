  - sideload.zip 与一份爬虫目标页面的 HTML 抓样（离线解析用）。

**完成记录**：`hs2-tools-csharp/HS2Tools.sln` 已建（`src/HS2Tools` WPF + `tests/HS2Tools.Tests` xUnit，测试项目 TFM 为 net8.0-windows 以引用 WPF 项目；`InternalsVisibleTo` 打通内部类型测试）。sideload.zip 已作 `EmbeddedResource` 内嵌。夹具改为**程序化合成**（见 02 §10.3）：合成 PNG 标记字节、Store/Deflate/脏 manifest zipmod、1500 条目大 zipmod（中央目录 ~186KB，强制渐进抓取）、autoindex HTML、HttpListener 内存测试服务器（Range/HEAD/慢速流式）。

## 阶段 1：核心服务移植（5~8 天，**成败关键，优先做**）

顺序：utils → scanner → downloader → sideloader（风险递增）。

1. `ConfigService` + `Models`：强类型配置读写（含"文件不存在返回空配置而非异常"的原版语义）。
2. `ScannerService`：目录扫描（子串排除、扩展名不敏感）、PNG 字节搜索解析、zipmod manifest 解析（`cleanString` 按 rune 过滤）、批量并行（`Parallel.ForEachAsync`）。
3. `DownloaderService` + `DownloadManager`：断点续传（206/200 分支）、代理（含认证）、进度节流、取消。
4. `SideloaderService`：HTML 目录解析（HtmlAgilityPack）、远程 ZIP 中央目录解析（渐进式尾部抓取 + 裸 DEFLATE）、两级信号量并发、可重入 Run。
5. `GameLauncherService`：`Process.Start` 启动游戏/工作室、`explorer /select,`、`SetThreadExecutionState` 防休眠。

**验证策略（必须执行）**：

- Go 版 CLI（`wails/cmd/scanner`、`wails/cmd/sideloader`）作为**基准工具**：对同一批夹具分别跑 Go 版与 C# 版，GUID/角色名提取结果逐一比对，要求完全一致。
- 单测覆盖：PNG 标记搜索（去首尾字节、IEND 截断）、zipmod cleanString（控制字符、非 ASCII、代理对）、EOCD 边界（comment、ZIP64 放弃）、DEFLATE 解压、Content-Range 解析。
- 爬虫全量跑通一次（真实站点 + 代理），结果 guid 数量与 Go 版相当。

**完成记录**：

- 5 个服务全部移植完成（`src/HS2Tools/Services/`），xUnit **104 项全绿**（含字节级边界用例与本地服务器集成测试）。
- Go scanner CLI 对照：7 项对照测试（readPngNames/Mods/Image、readZipMod、scanDir 含遍历顺序、两个批量）全过；测试自动在临时副本构建基准 CLI（不改原仓库；go.mod `go 1.25.0` 与本机 go1.24 的兼容处理见 02 §10.3）。
- Go sideloader CLI 真实爬取基准 12,472 个；C# 对照爬取 12,366 个（29 分钟），**guid 重合度 99.06%**，相对路径差异 75 个（重复 guid 的多目录选路，非提取错误，见 02 §10.3）。
- 实施期发现并修复 .NET 平台陷阱 3 个（系统代理、h2 无效设置、200 全量）+ 安全防御 2 项，详见 [02-迁移方案.md](02-迁移方案.md) 第 10 节——**阶段 3 涉及网络下载前必读**。

## 阶段 2：应用骨架（2 天）

- `App.xaml.cs`：服务容器初始化、异常兜底（`DispatcherUnhandledException` 记日志+提示）、主窗口启动。
- `WindowManager`：窗口单例 + Show/Hide/Activate + 主窗关闭退出。
- 单主题 `ResourceDictionary`（颜色/画刷集中定义，控件一律 `DynamicResource`——为 A7 后期双主题留口）。
- `MainWindow`：导航入口 + 首页静态布局占位。
- `ConfigService` 接入：游戏路径设置 + `HoneySelect2.exe` 校验徽标。

**完成记录**：全部落实。`Services/ServiceContainer.cs`（单例容器，代理经 `Config.GetProxyString` 即时生效）；`Windows/WindowManager.cs`（子窗口 Closing 拦截为 Hide 保状态，主窗关闭即退出）；`Themes/Theme.xaml`（颜色/画刷集中定义）；`Views/` MainWindow（游戏路径卡片 + 红绿校验徽标 + 7 导航按钮）+ 7 占位窗口；`ViewModels/MainWindowViewModel.cs`（CommunityToolkit.Mvvm）。新增 7 项测试（VM 校验/持久化 + WindowManager STA 冒烟含 8 窗口 XAML 实例化），`dotnet run` 启动冒烟通过。

## 阶段 4：打磨打包（2~3 天）

- 全局异常提示与操作反馈统一；长任务按钮防重入；空状态/无图占位。
- 发布：`dotnet publish -c Release -r win-x64 --self-contained -p:PublishSingleFile=true`（内嵌 sideload.zip 随程序集资源打包）。
- 冒烟清单：首次启动 → 设路径 → 扫描 → 浏览卡片 → 下载（含代理）→ 整理场景 → 爬虫更新 → 启动游戏。

## 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 远程 ZIP 解析移植出错（zipreader） | **高** | 阶段 1 最先移植并配足单测；与 Go CLI 输出对照；保留渐进抓取/前插/EOCD 末尾校验全部边界行为。**→ 已消解**：EOCD/ZIP64/截断窗口/Store/Deflate 单测全过，真实站点对照 12,366/12,472 重合 99.06% |
| PNG 字节搜索行为偏差（编码、乱码名） | 中 | 真实卡片夹具回归；注意 Go 与 .NET 无效 UTF-8 处理差异，测试期确认可接受。**→ 合成夹具（含 UTF-8 中文名）与 Go CLI 对照一致；乱码名差异待阶段 3 用真实卡片终验** |
| 爬虫目标站点结构变化 | 中 | 选择器逻辑与原版一致即可，非迁移引入的风险；失败路径记日志便于排障 |
| WPF 无内置 VirtualizingWrapPanel | 低 | 自带实现（约 200 行）或按行分组虚拟化 |
| 双主题后期补做成本 | 低 | 阶段 2 起强制 `DynamicResource`，不留硬编码色值。**→ 已落实**（Themes/Theme.xaml 集中定义） |
