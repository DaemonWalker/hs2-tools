# 01 现状分析

本文档是对现有 HS2-Tools（Wails + Go + React）代码库的完整分析，作为迁移的依据。
所有"死代码"判定均经过全量搜索核实（调用点/导入点为零）。

## 1. 技术栈与规模

| 层 | 技术 | 规模 |
|---|---|---|
| 桌面框架 | Wails v2.12（Go 后端 + WebView2 前端，单进程） | — |
| Go 后端 | Go 1.25，第三方依赖仅 `goquery`（HTML 解析） | **约 2,336 行**：`app.go` 572 + `internal/` 1,460 + `cmd/` 247 |
| 前端 | React 18 + TS + AntD 5 + Zustand + Tailwind + ahooks | **约 8,000 行 TS/TSX（70 文件）+ 2,000 行 CSS** |
| 内嵌资源 | `wails/resources/sideload.zip`（BetterRepack Mod 数据库，内含 sideload.json） | — |

## 2. Go 后端 internal 包

### 2.1 scanner（628 行，`wails/internal/scanner/`）

- **目录扫描** `ScanDirectory`：`filepath.Walk` 递归；排除目录判定是**子串匹配**（`strings.Contains(name, exclude)`）；扩展名过滤大小写不敏感。
- **PNG 角色卡解析**（`png.go`，迁移重点）：**不是标准 PNG chunk 解析，而是暴力字节搜索**。
  - 标记对：角色名 `fullname`→`personality`，Mod GUID `ModID`→`Slot`（Unity BinaryWriter 序列化上下文关键词）。
  - 命中区间后**去掉首尾各 1 字节**，再 `TrimSpace`；原始字节直接按 UTF-8 转字符串；结果 map 去重且**无序**。
  - 缩略图：从文件末尾**反向搜索最后一个 `IEND`**，截断点 = 命中位置 +1（覆盖 CRC），截出纯 PNG 图像部分做 base64。
  - 批量函数：taskChan + N 个 worker + WaitGroup + Mutex；文本类 8 并发、图像类 4 并发；失败静默跳过。
  - 注意：`ReadPngPageDataBatch` 同一文件被读盘 **2 次**（名称一遍、图像一遍）——C# 版一次读盘。
- **zipmod 解析**（`zipmod.go`）：`archive/zip` 找 `manifest.xml`（大小写不敏感）→ XML 反序列化（guid/name/version）。
  - 关键 hack `cleanString`：**只保留 ASCII 32~126**，Guid/Name 清洗、**Version 不清洗**（防御 mod 作者写入的控制字符；会截掉中文，必须复刻以保 GUID 一致）。
- 其他：`MoveFile`（os.Rename，失败回退全量读内存复制——C# 直接用 `File.Move`）、`CheckTargetDir`、`FileExists`（存在且扩展名为 .png）。

### 2.2 downloader（286 行，`wails/internal/downloader/`）

- `NewDownloader(proxyURL)` + `Download(url, output, resume, onProgress)` + `Cancel()`。
- 断点续传：`Stat` 已存在文件大小 → `Range: bytes={pos}-` 头；`206` 从 `Content-Range` 解析总长；`200`（服务器不支持 Range）回退全量 Truncate。
- UA 固定 `hs2-tools-downloader/1.0`；无超时（靠 ctx 取消）；32KB 缓冲区循环；进度节流 **200ms 或 64KB**；速度只计本次会话下载量。
- 代理：`http.Transport.Proxy`；认证由 app.go 拼 `proto://user:pass@host`。

### 2.3 sideloader（415 行，`wails/internal/sideloader/`，全项目最复杂）

爬取 `https://sideload.betterrepack.com/download/AISHS2/` 目录列表，**对每个远程 zipmod 只发 3~18 次 HTTP Range 小请求**（不下载整文件）提取 GUID：

1. goquery 解析 autoindex 页面（`table#indexlist tr`，**跳过前 2 行**），`QueryUnescape` 解码 href，`.zipmod` 与目录分流；mod 级并发 10、目录级并发 3（信号量）。
2. `HEAD` 拿文件大小 → 从尾部按 16KB 递增抓取（最多 16 次 / 256KB 窗口），新 chunk **前插**累积，逐步尝试解析中央目录。
3. `findEOCD`：窗口内反向扫 EOCD 签名（0x06054b50），且要求 **EOCD 精确位于窗口末尾**（含 comment 长度校验，防巧合字节）。
4. 读中央目录：条目数/CD 大小/CD 偏移定偏移读取；`cdOffset == 0xFFFFFFFF`（ZIP64）直接放弃；CD 不完整返回 null 触发扩大窗口重试。
5. 找 `manifest.xml` 条目 → 对本地文件头偏移再发 Range（201 字节）→ 解析本地头（失败回退 `30 + nameLen` 假设无 extra）→ 第三次 Range 拉压缩数据 → Store 直接用 / **裸 DEFLATE 流**解压 → `strings.Index` 暴力截取 `<guid>`。
6. 请求头显式 `Accept-Encoding: identity`；HTTP 客户端 60s 超时；`onProgress` 的 total 恒为 0；`Cancel()` 只置标志位（已发出的请求不中断）；`Run` 非可重入。

### 2.4 utils（139 行，`wails/internal/utils/`）

- `config.go`：`os.UserConfigDir()/hs2-tools/`（Windows = `%AppData%/hs2-tools`）下 `setting.json` / `localMods.json` 读写；`LoadJSON` 文件不存在返回 `(nil, nil)` 而非错误。
- `zip.go`：`ExtractZipJSON/ExtractZipEntry`，按**精确名**（区分大小写）找 zip 条目。

## 3. API 面（app.go 绑定层）

`app.go` 共 **约 37 个绑定方法 + 4 个事件**。前端实际使用约 22 个方法。

**事件**：`download:progress`、`download:complete`、`sideloader:progress`、`sideloader:complete`。

## 7. 迁移时必须复刻的行为细节（正确性关键）

1. PNG 字节搜索：命中区间**去首尾各 1 字节** + Trim；结果去重无序；IEND 反向搜索、截断点 +1。
2. zipmod `cleanString`：只留 ASCII 32~126；Guid/Name 清洗、Version 不清洗；注意 .NET `char` 是 UTF-16 码元，须按 rune 处理避免半个代理对。
3. 远程 ZIP：EOCD 须精确位于抓取窗口末尾；ZIP64 放弃；CD 不完整返回 null 重试扩大窗口；本地头解析失败回退 `30 + nameLen`；chunk 前插累积；**裸 DEFLATE**（C# 用 `DeflateStream`，不能用 `ZLibStream`）。
4. 下载：`Range` 头、206 解析 `Content-Range`、200 回退全量；节流 200ms/64KB；UA `hs2-tools-downloader/1.0`。
5. 爬虫：索引表跳过前 2 行；`Uri.UnescapeDataString`；`Accept-Encoding: identity`；60s 超时。
6. 目录扫描排除规则是**子串匹配**；扩展名大小写不敏感。
7. 下载 URL 拼接与输出路径规则：`{baseURL}{相对路径}` → `{dir}/{name}.zipmod`。
