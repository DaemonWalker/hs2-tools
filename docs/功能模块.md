# 功能模块

应用采用单窗口主壳：左侧导航切换工作台与 7 个功能页面，所有页面实例缓存并保持状态。

## 主窗口与工作台（MainWindow / HomeView）

- **自定义标题栏**：顶部通栏显示应用标识与最小化、最大化/还原、关闭按钮，保留拖动、双击最大化/还原和边缘调整窗口大小行为。
- **全局游戏切换器**：侧栏底部“当前游戏”下拉框按 `GameProfiles.All` 提供 HS2 / KK / KKS，所有页面均可切换；切换后各页面自动按新游戏目录重扫，扫描/爬虫运行中禁止切换。
- **游戏路径**：选择当前游戏目录，按该游戏 exe（如 `HoneySelect2.exe` / `Koikatu.exe` / `KoikatsuSunshine.exe`）自动校验（红/绿状态点 + 提示文案）；各游戏路径独立保存，各功能以路径有效为门控。
- **数据分析**：三阶段扫描（Mod → 场景 → 角色卡），分批 500 带进度；Mod 阶段顺带扫描 `unusedmods/` 中的 `.zipmod` 与已禁用的 `.zipmod_`（单独成表，不进 LocalMods），数据概览"本地 Mods"后括号显示未使用数；分析完成后若发现 unusedmods 里有被卡片引用、或 manifest 声明了 shader（MaterialEditor）且 mods 中没有同 GUID 的 Mod，弹确认框，确认后移入 `mods/MyMods/`、将 `.zipmod_` 恢复为 `.zipmod`（同名加 _2/_3 后缀）并补录 LocalMods（shader 包不被卡片按 GUID 引用，含 shader 信息即视为在用）。Mod 使用统计合并规则为"角色覆盖场景"；统计数据按游戏隔离。卡片引用、zipmod manifest 与站点索引的 GUID 仅移除控制字符，保留 Unicode 与首尾空格，匹配不 Trim。分析完成后，仅对原始 GUID 无精确匹配但 Trim 后相同的结构化人物/场景卡提示修复，逐卡显示路径与替换关系并由用户确认，不再自动改写或复制 zipmod；存在无空格的精确本地候选时优先作为目标，否则仅接受唯一本地候选。每张卡执行前复核文件指纹，在原卡旁生成带时间戳和随机标识的 `.guid-backup.bak` 独立备份（不参与卡片扫描，永不自动删除或覆盖），以局部字节补丁重写 KKEx/UAR 引用并同步修正 MessagePack、BlockHeader、块数据与 trailer 长度，临时文件复验通过后才替换原卡，随后更新引用统计和 SQLite 缓存。回退字节扫描解析的卡片不提供不安全重写。分析结果同时持久化为 Mods 窗口去重/整理/清理的数据源缓存（完整 zipmod 条目含重复 guid 且覆盖 unusedmods、人物/场景分卡引用集、完成时点）。另有 `analysis-cache.db` 增量缓存：按游戏和目录类型记录文件大小、修改时间与解析结果，未变化的 zipmod/卡片重新分析时不再读盘，变化或缓存版本不符才重新解析；网格、详情和场景整理共用该缓存。
- **相近 Mod 匹配**：精确本地与精确 Sideload 均未命中时，按“相同基础名 + 尾部修订号”双向生成候选，覆盖 `abc ↔ abc001`、`abc ↔ abc_v2` 与 `abc001 ↔ abc002`；基础名至少 3 字符且含字母，无分隔符的裸数字后缀仅接受 2～4 位，支持 `_-. ` 分隔符及 `v/ver/rev` 标记，不使用普通子串或编辑距离。首页显示候选数量，表格展示需要/候选 GUID、来源、匹配依据、名称版本和路径/URL；所有候选默认不选，同一需要 GUID 只能单选一个。本地候选执行前复核源 GUID，始终复制到 mods 并仅改副本 manifest GUID（原名、版本与源文件保留）；Sideload 候选以需要 GUID 作为任务 Id 和文件名，下载提交前复核远端实际 GUID、改写并复验，失败删除临时文件，完成事件只在改写成功后发出。执行期间禁止扫描与切游戏；进行中/已完成下载隐藏对应候选，失败下载的候选重新出现。
- **快速启动**：一键启动当前游戏 / 工作室（exe 名取当前游戏档案）。
- **Sideloader 更新**：运行/停止（停止需确认，停止后不落盘、状态显示"已停止"，在飞请求经 CancellationToken 即时中断）；爬虫起点取当前游戏档案（KK/KKS 从 KKEC 根目录遍历全部子 Modpack；单目录生产者 + 10 个异步 Mod 消费者，避免递归目录调度死锁），单个 Mod 的未预期异常只记录并计入失败，不中断其余 Mod 或整轮更新，结果按数据源写入 `analysis-cache.db`（KK/KKS 共享 kkec 库）。
  - 更新保护：空结果保留旧库；有目录/Mod 抓取失败时询问用户是否使用本次结果，确认前不落盘且禁止切换游戏，拒绝则保留旧库，接受则应用本轮结果并在扫描记录中标记；404 视为远端已删除、自然淘汰，不算失败。
  - 完整成功或用户确认使用的扫描按合并语义更新：本轮见到的条目刷新 last-seen，连续两次已应用扫描未见才淘汰；内嵌/空回退库的首次更新覆盖种子库，不做合并。
  - 增量爬取：本地记录的 autoindex `Last modified` 不晚于本站当前时间时零请求复用旧 GUID；本地时间更晚或记录不存在时发 Range 请求，日期缺失或无法解析时仅在原始指纹完全一致时复用，其余保守重抓。目录中 `Size` 为 `0` 的 zipmod 直接跳过，不请求文件且不计入发现或失败数。运行中的已发现/已处理均只统计 Mod 文件（不含目录），已发现不再取去重后的成功 GUID 数。
- **缺失补全**：列出"被引用但本地缺失且 sideload 库中有"的可下载 Mod，一次性加入全局串行下载队列（下载窗口立即显示全部等待任务，失败不阻断，下载 base URL 按当前游戏），结束显示汇总（成功/失败数）；不在 Sideload 数据库中的缺失项单独提示，不能自动下载。
- **数据概览**：本地 Mod 数、被引用 Mod 数、总引用次数、可下载数（被引用、本地不存在但 Sideload 库中存在）、缺失数（被引用、本地与 Sideload 库中均不存在）；两类依赖都为 0 才显示"已就绪"，无扫描数据时不显示。

## 角色卡浏览（CharaView）

- 左侧目录树按磁盘结构显示全部目录（含空目录，跳过符号链接）；默认选中根目录，点击目录只展示该目录直接包含的卡片，不混入子目录；刷新或切换游戏后回到根目录。
- CardGridControl 虚拟化网格：缩略图、分批加载（每批 24）、滚动加载、收藏（♥）、四种排序（收藏优先/名称 A-Z/名称 Z-A/路径，zh-CN 文化规则 + .NET 10 数值自然排序，card2 排在 card10 前）。图像不再经过 Base64，仅提取真 IEND 前的 PNG 区间交给后台按显示宽度与 DPI 解码并 Freeze，不让位图流保留追加的卡片游戏数据；搜索/排序保留缩略图 LRU，显式刷新才清空。
- 搜索框逐键实时过滤（子串匹配），搜索范围与“共 N 个”统计均限定为当前目录正在展示的卡片。
- 详情面板：大图、Mod 依赖列表（已拥有/缺少标记）、单项下载、**一键下载缺失**、真实修改时间与文件大小、打开所在文件夹；点击依赖 GUID 可打开对应 Mod 详情；名称、Mod 与图像一次读盘取得，命中 SQLite 元数据缓存时只读取图像。
- 卡片解析按卡头标记自动识别游戏格式（HS2 与 KK/KKS 卡片都能解析，角色名按各游戏字段规则拼接）。
- 切换游戏或修正游戏目录后自动重扫；未设置路径时显示引导，目录缺少当前游戏 exe 时清空网格并提示路径错误，避免误展示其他游戏卡片。

## 场景库（SceneView）

- 场景网格（同角色卡浏览，16:9 卡片）；切换游戏或修正游戏目录后自动重扫，路径无效时同样清空并提示。
- **智能整理**：按"角色名子串匹配场景卡角色名"创建整理任务；批量执行（进度 0~50 分析 / 50~100 移动）；所有待执行任务共享一次目录扫描和角色名解析，移动仍按任务顺序执行，前序任务已移动的场景不重复处理；移动到 `scene/hs_tools_<文件夹名>/`（已整理目录自动排除）；单文件失败记日志并计数，完成文案显示"（N 个失败）"；执行中删除/清空按钮置灰。

## 本地模组（ModsView）

- DataGrid 表格：名称、GUID、版本、使用次数、路径与详情操作；列排序、虚拟化，双击行或点击“详情”打开独立详情窗口。
- 筛选：所有 / 未使用 / GUID 可能重复；GUID 可能重复使用首页「开始分析」持久化的完整条目（需先分析，不使用会折叠大小写重复项的 LocalMods），仅检查 `mods/`，按 GUID `Trim` 后不区分大小写分组，显示组内至少 2 个条目的全部文件，因此完全相同、仅 Trim 后相同、Trim 且忽略大小写后相同的 GUID 都能查出，空白 GUID 不参与；搜索框逐键匹配 GUID、名称、完整文件路径与 Sideload URL（不区分大小写），可与当前筛选叠加；统计卡（Mod 数、被引用数、总引用次数）；刷新重扫（防重入）。
- Mod 详情：显示名称、GUID、版本、文件大小、修改时间、完整文件路径和 Sideload URL（无链接显示 `-`），并原样展示 zipmod 压缩包内 `manifest.xml`；点击 Sideload URL 使用默认浏览器打开该 Mod 所在的 BetterRepack 目录列表（去掉 zipmod 文件名，不直接触发下载）；可在资源管理器中定位文件。角色卡、场景卡和单卡查看器的依赖 GUID 均可打开详情；本地缺失的 Mod 显示 GUID、URL 和无法读取 manifest 的提示。
- 使用次数匹配大小写不敏感。
- **去重 Mods**：以「开始分析」持久化的完整条目缓存为数据源（不重扫磁盘；从未分析过提示先分析，确认文案标注缓存时点），只针对 mods 目录条目；相同 GUID 按"版本号高 → 体积大 → 修改日期新"裁决保留一个（全平按路径词典序取确定结果）；弹确认框后落选文件移动到游戏根目录 `duplicatemods/`（重名自动加 `_2` 后缀，下载目录内文件跳过；缓存时点后已消失的文件按存在性校验跳过），LocalMods 更新为各 GUID 最优、条目缓存同步移除落选者；与刷新互斥防重入。普通扫描遇重复 GUID 也按同一裁决规则取最优。
- **清理 Mods**：以「开始分析」缓存为数据源，覆盖 `mods/` 和 `unusedmods/`，找出未被人物/场景卡引用、manifest 未声明 shader 且 GUID 存在于当前 Sideload 数据库的文件（GUID 匹配大小写不敏感，排除下载目录与 `mods/MyMods/`）；未收录文件（含整理后禁用的 `.zipmod_`）不满足清理条件，不会被删除。弹确认框明确提示永久删除且无法撤销，确认后逐文件删除。文件已消失则跳过、删除失败记日志并不中断，成功删除项同步移出条目缓存，LocalMods 按 mods 目录剩余条目重建；与刷新/去重/整理互斥防重入。
- **整理 Mods**：同样走「开始分析」缓存（不重扫磁盘），处理完整 zipmod 条目（覆盖 `mods/`、`unusedmods/`，包含下载目录与 `mods/scenemods/`；unusedmods 同时识别 `.zipmod_`）。必须先有 Sideload 扫描记录，否则提示先运行「Sideloader 更新」，不执行任何移动；先按去重规则跨 mods/unusedmods 裁决同 GUID 重复，落选 → 游戏根目录 `duplicatemods/`；站点索引中仅大小写不同的重复 GUID 按相对路径字典序取较小者；再对全部赢家分类：GUID 在索引中 → `mods/<站点相对目录>/`（无目录部分进 mods 根目录，已在目标目录且扩展名正确则不动），GUID 不在索引中但被人物/场景卡引用或 manifest 声明 shader → `mods/MyMods/` 平铺并保持 `.zipmod`，GUID 不在索引中且未被引用、不含 shader → 游戏根目录 `unusedmods/` 平铺并改名为 `.zipmod_` 防止游戏加载；已经在正确位置和状态的文件不重复移动，旧 `unusedmods/*.zipmod` 可只在原目录改名。站点相对路径含 `..` 或 rooted 时按不在索引处理并写 ErrorLog。弹确认框列出重复、站点归位、非索引用中保留、非索引未使用禁用各类数量（为 0 省略）后执行，文件消失/移动失败记日志跳过不中断，重名自动加后缀；LocalMods 与条目缓存以最终落点写回（仅 mods 下的赢家进入 LocalMods，unusedmods 赢家仍保留在完整条目缓存，移动失败的落选者保留供下次整理）；与刷新/去重/清理互斥防重入。

## Sideload 数据库（SideloadView）

- 浏览 BetterRepack 全量库（12k+ 条目）：GUID、相对路径、已存在/缺失状态；按数据源分库（HS2 独占 hs2 库，KK/KKS 共享 kkec 库），随当前游戏切换；kkec 无内嵌库，需先在主窗口运行一次爬虫更新。
- 上次扫描时间与结果持久化到 `analysis-cache.db` 的 `sideload_scan_meta` 表（成功结束 / 已停止 / 异常终止 / 部分失败，含发现数量、失败计数、是否应用部分结果或错误原因），统计三卡下方实时显示「上次扫描」（meta 变更只刷新该行，不重建整表）；整理 Mods 以 meta 存在为启用前提，无记录时拒绝整理。旧 JSON 库与 meta 首启自动迁入 SQLite，原文件保留为 `.migrated` 备份。
- 300ms 防抖搜索（版本号作废旧查询，快速输入不错乱）。
- 缺失条目行内下载（按钮状态与其他页面发起的下载实时联动）。

## 下载任务（DownloadView）

- 所有下载入口共用全局串行队列：同时只下载一个 Mod，其余任务立即显示为“等待中”，前一个到达终态后自动开始下一个。
- 单文件超过 50 MiB 且服务器实际支持 Range 时，按 50 MiB 分段、最多 4 路异步并发下载；分段直接按偏移写入 `.zipmod.part`，每 1 MiB 及分段结束保存 `.part.json` 续传状态，取消/失败后可按分段续传。Range 被忽略或远端文件变化时回退单流重下；瞬时失败的分段最多尝试 3 次并指数退避。全部完成后先校验 ZIP/manifest，再改为正式 `.zipmod` 并标记完成；小文件与旧版 `.zipmod` 半成品保持原单流续传路径。
- 统计栏：活跃数（等待中 + 下载中）、失败数、总速度（仅实际下载任务）。
- 四个 Tab：全部 / 进行中（等待中 + 下载中）/ 已完成 / 失败（**失败 Tab 仅含 Failed，不含 Cancelled**）。
- 任务项：等待状态、进度条、速度、剩余时间、取消、重试；全部取消、清除完成（清所有非等待/下载中任务）。
- 切换页面不中断下载，返回时复用缓存视图；同名任务重试自动去重行。

## 卡片探索器（CardExplorerView）

- 打开单个 PNG 卡片：人物卡 / 场景卡两种布局。
- 显示大图、名称、描述、Mod 依赖（含缺失标记）、场景人物列表；无图/空列表均有占位文案；解析失败显示错误页。

## 系统设置（SettingsView）

- 代理表单：地址（http/https/socks5，留空直连）、用户名、密码；非法地址红字提示。
- 防休眠开关（`SetThreadExecutionState`），应用启动时按配置恢复。
- 改动即时生效并防抖持久化。
