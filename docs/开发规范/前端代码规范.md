# 前端代码规范

本文档定义 HS2-Tools 项目中 React + TypeScript 前端代码（`wails/frontend/`）的编写规范。

## 命名规范

### 文件命名

| 类型 | 命名规范 | 示例 |
|------|----------|------|
| 组件 | PascalCase | `MyComponent.tsx` |
| 工具函数 | camelCase | `myUtil.ts` |
| Store | camelCase + Store | `myStore.ts` |
| Hook | camelCase + use | `useMyHook.ts` |
| 样式 | camelCase + .css | `myStyle.css` |
| 常量 | SCREAMING_SNAKE_CASE | `constants.ts` |

### 变量命名

```typescript
// 变量 - camelCase
const fileCount = 0

// 常量 - SCREAMING_SNAKE_CASE
```

## UI 组件规范

### 优先使用 Ant Design

**原则：优先使用 Ant Design 提供的组件，而非自行实现。**

```typescript
// ✅ 推荐：使用 Ant Design 组件
import { Drawer, Button, Modal, Card } from 'antd'

// 使用 Drawer 组件
<Drawer
  title="详细信息"
  placement="bottom"
  open={visible}
  onClose={handleClose}
>
  <Content />
</Drawer>

// ❌ 避免：自行实现抽屉
<div className="custom-drawer">
  <div className="drawer-header">...</div>
  <div className="drawer-body">...</div>
</div>
```

**原因：**
- Ant Design 组件经过充分测试，稳定可靠
- 内置动画、响应式、无障碍支持
- 统一的设计语言和交互体验
- 减少维护成本

**例外情况（允许自定义实现）：**
- Ant Design 没有提供该组件
- 需要高度定制化，Ant Design 无法满足需求
- 自定义组件更简单且复用性低

### 自定义组件原则

如需自定义组件，应遵循：
- 保持与 Ant Design 一致的设计语言
- 支持相同的 API 模式（如 `open`/`onClose`）
- 添加适当的 TypeScript 类型定义

## React 规范

### 组件结构

```typescript
// 1. 导入
import { FC, useState, useEffect } from 'react'
import { Button } from 'antd'
import { useMyStore } from './store'

// 2. Props 接口
interface MyComponentProps {
  title: string
  onSubmit: (data: FormData) => void
}

// 3. 组件实现
export const MyComponent: FC<MyComponentProps> = ({
  title,
  onSubmit
}) => {
  // 4. Hooks
  const [count, setCount] = useState(0)
  const store = useMyStore()

  // 5. Effects
  useEffect(() => {
    // 副作用
  }, [])

  // 6. 处理函数
  const handleClick = () => {
    setCount(c => c + 1)
  }

  // 7. 渲染
  return (
    <div>
      <h1>{title}</h1>
      <p>{count}</p>
      <Button onClick={handleClick}>Click</Button>
    </div>
  )
}
```

### Hooks 规范

```typescript
// ✅ Hooks 在组件顶层调用
const MyComponent: FC = () => {
  const [state, setState] = useState(0)
  const ref = useRef(null)
  const store = useMyStore()

  useEffect(() => {
    // ...
  }, [])

  // ...
}

// ❌ 不要在条件语句中调用 Hooks
const BadComponent: FC = () => {
  if (condition) {
    const [state] = useState(0)  // 错误！
  }
}

// ❌ 不要在循环中调用 Hooks
const BadComponent2: FC = () => {
  for (let i = 0; i < 3; i++) {
    const [state] = useState(0)  // 错误！
  }
}
```

### 自定义 Hooks

```typescript
// useMyHook.ts
import { useState, useEffect } from 'react'

interface UseMyHookOptions {
  initialValue?: number
}

interface UseMyHookReturn {
  value: number
  increment: () => void
  decrement: () => void
}

export const useMyHook = (options?: UseMyHookOptions): UseMyHookReturn => {
  const [value, setValue] = useState(options?.initialValue ?? 0)

  const increment = () => setValue(v => v + 1)
  const decrement = () => setValue(v => v - 1)

  return { value, increment, decrement }
}
```

## Zustand Store 规范

### Store 结构

```typescript
// counterStore.ts
import { create } from 'zustand'

interface CounterState {
  // 状态
  count: number
  isLoading: boolean

  // 简单 setter
  setCount: (count: number) => void
  setLoading: (loading: boolean) => void

  // 计算操作
  increment: () => void
  decrement: () => void

  // 异步操作
  fetchCount: () => Promise<void>
}

export const useCounterStore = create<CounterState>((set, get) => ({
  count: 0,
  isLoading: false,

  setCount: (count) => set({ count }),
  setLoading: (isLoading) => set({ isLoading }),

  increment: () => set((state) => ({ count: state.count + 1 })),
  decrement: () => set((state) => ({ count: state.count - 1 })),

  fetchCount: async () => {
    set({ isLoading: true })
    try {
      const response = await fetch('/api/count')
      const data = await response.json()
      set({ count: data.count })
    } finally {
      set({ isLoading: false })
    }
  }
}))
```

### Store 使用

```typescript
// ✅ 只订阅需要的字段（性能优化）
const count = useCounterStore(state => state.count)
const increment = useCounterStore(state => state.increment)

// ❌ 避免订阅整个 store
const store = useCounterStore()  // 会导致不必要的重渲染
```

## 后端调用规范

### 调用方式

前端不直接调用 Wails 生成的绑定，统一通过 `src/logic/ipcUtils.ts` 兼容层调用：

```typescript
// ✅ 通过 ipcUtils 调用
import ipcUtils from '../logic/ipcUtils'

const mods = await ipcUtils.readPngForMod(path)

// ❌ 避免在业务代码中直接引用生成的绑定
import { ReadPngForMod } from '@wailsjs/go/main/App'  // 仅在 ipcUtils.ts 中使用
```

### 接口命名

```typescript
// ipcUtils 方法：camelCase，与 Go 导出方法一一对应
readPngForMod     // 对应 Go: ReadPngForMod
triggerDownload   // 对应 Go: TriggerDownload
saveSettings      // 对应 Go: SaveSettings

// 事件监听：on + 事件名
onDownloadProgress
onDownloadComplete
onSideloaderProgress
```

### 事件监听

事件监听返回取消订阅函数，组件卸载时必须调用：

```typescript
useEffect(() => {
  const unsubscribe = ipcUtils.onDownloadProgress((data) => {
    // 处理进度
  })
  return unsubscribe  // 卸载时取消订阅
}, [])
```

### 新增后端接口流程

1. 在 `wails/app.go` 的 `App` 上添加导出方法
2. 重新运行 `wails dev` 生成绑定
3. 在 `ipcUtils.ts` 中封装 camelCase 接口
4. 业务代码通过 `ipcUtils` 调用

## 注释规范

### 文件头注释

```typescript
/**
 * @fileoverview 文件描述

```

### 函数注释

```typescript
/**
 * 函数描述
 * @param param1 - 参数1描述
 * @param param2 - 参数2描述
 * @returns 返回值描述
 * @example
 * const result = myFunction('value', 123)
```

```typescript
const cached = computeExpensiveValue()
```

## 错误处理

### 同步错误

```typescript
try {
  const result = riskyOperation()
  processResult(result)
} catch (error) {
  console.error('Operation failed:', error)
  showErrorMessage('操作失败，请重试')
}
```

### 异步错误

```typescript
// ✅ async/await + try-catch
async function fetchData() {
  try {
    const mods = await ipcUtils.readPngForMod(path)
    return mods
  } catch (error) {
    console.error('Fetch failed:', error)
    throw new Error('数据加载失败')
  }
}

// ✅ Promise catch
fetchData()
  .then(data => console.log(data))
  .catch(error => console.error(error))
```
