# 贡献指南

本文档介绍如何为 HS2-Tools 贡献代码。

## 开发流程

### 1. Fork 仓库

1. 访问项目 GitHub 页面
2. 点击 "Fork" 按钮
3. 克隆你的 Fork 到本地

```bash
git clone https://github.com/YOUR_USERNAME/hs2-tools.git
cd hs2-tools
```

### 2. 创建分支

```bash
# 基于 main 创建功能分支
git checkout -b feature/my-new-feature

# 或修复分支
git checkout -b fix/some-bug
```

### 3. 开发

1. **安装依赖**

```bash
npm install
(cd wails/frontend && npm install)
```

2. **启动开发模式**

```bash
npm run wails:dev
```

3. **编写代码**

遵循 [代码规范](./代码规范.md) 进行开发。

### 4. 提交前检查

```bash
# 前端类型检查与构建
cd wails/frontend && npm run build && cd ../..

# 代码检查
npm run lint

# 格式化
npm run format
```

### 5. 提交代码

```bash
# 添加修改的文件
git add src/some-file.ts

# 提交
git commit -m "feat: 添加新功能"

# 推送到你的 Fork
git push origin feature/my-new-feature
```

### 6. 创建 Pull Request

1. 访问原仓库页面
2. 点击 "New Pull Request"
3. 选择你的分支和 main 分支
4. 填写 PR 描述
5. 提交 PR

## 提交信息规范

使用 [Conventional Commits](https://www.conventionalcommits.org/) 规范：

```
<type>(<scope>): <subject>

<body>

<footer>
```

### Type

| 类型 | 说明 |
|------|------|
| `feat` | 新功能 |
| `fix` | Bug 修复 |
| `docs` | 文档更新 |
| `style` | 代码格式（不影响功能） |
| `refactor` | 重构 |
| `perf` | 性能优化 |
| `test` | 测试相关 |
| `chore` | 构建/工具相关 |

### 示例

```
feat: 添加角色卡导出功能

- 支持导出为 JSON 格式
- 支持批量导出

Closes #123
```

```
fix(mod): 修复 Mod 列表加载失败的问题

当本地 Mod 数量超过 1000 时会出现性能问题，
现在使用虚拟滚动优化。

Fixes #456
```

## 代码审查清单

提交 PR 前请检查：

### 功能

- [ ] 功能按预期工作
- [ ] 处理了边界情况
- [ ] 错误处理完善

### 代码质量

- [ ] 代码符合 [代码规范](./代码规范.md)
- [ ] TypeScript 类型完整
- [ ] 没有 `any` 类型
- [ ] 函数和变量命名清晰

### 测试

- [ ] 添加了单元测试（如适用）
- [ ] 手动测试通过
- [ ] 边界情况测试

### 文档

- [ ] 更新了相关文档
- [ ] 添加了代码注释
- [ ] 更新了 CHANGELOG

## 分支策略

```
main (受保护)
  ↑
feature/* - 功能分支
  ↑
fix/*     - 修复分支
  ↑
docs/*    - 文档分支
```

### 分支命名

| 类型 | 命名 | 示例 |
|------|------|------|
| 功能 | `feature/<描述>` | `feature/chara-export` |
| 修复 | `fix/<描述>` | `fix/mod-loading` |
| 文档 | `docs/<描述>` | `docs/api-update` |
| 重构 | `refactor/<描述>` | `refactor/store` |

## 报告 Bug

### 提交前检查

- [ ] 搜索现有 issues，避免重复
- [ ] 确认使用最新版本
- [ ] 阅读文档确认不是配置问题
