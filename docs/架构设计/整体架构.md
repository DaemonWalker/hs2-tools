## 应用模型

Wails 应用为**单进程**架构：Go 后端与 WebView 前端运行在同一个应用内，通过 Wails 运行时桥接通信，不再有 Electron 的「主进程 / 渲染进程」之分。

### 1. Go 后端

**文件**: `wails/main.go`、`wails/app.go`

**职责**:
- 创建和管理应用窗口（1280×720，最小 1000×600）
- 通过 `//go:embed all:frontend/dist` 内嵌前端产物
- 通过 `Bind` 将 `App` 结构体的导出方法暴露给前端
- 执行系统级操作（文件系统、网络、启动游戏进程）
- 通过 `EventsEmit` 向前端推送异步事件（下载进度、爬虫进度等）

**特点**:
- Go 后端与前端共处一个应用进程
- 前端产物直接嵌入可执行文件，单文件分发
- BetterRepack 基础数据包通过 `//go:embed resources/sideload.zip` 内嵌

### 2. 前端 (React)

**文件**: `wails/frontend/src/main.tsx`

**职责**:
- 渲染用户界面
- 处理用户交互
- 管理前端状态
- 通过生成的 wailsjs 绑定调用 Go 方法、监听事件

**特点**:
- 运行在系统原生 WebView 中（Windows 为 WebView2）
- 使用 `react-router-dom` 的 HashRouter 管理路由
- 无法直接访问系统 API，所有系统操作通过 Wails 绑定调用 Go 方法

### 3. ipcUtils 兼容层

**文件**: `wails/frontend/src/logic/ipcUtils.ts`

**职责**:
- 封装 `wailsjs/go/main/App` 生成的绑定函数
- 提供与旧 Electron `ipcRenderer` 同形的接口（camelCase 方法名）
- 封装 `EventsOn`/`EventsOff` 事件监听，返回取消订阅函数

```typescript
// wails/frontend/src/logic/ipcUtils.ts
import { ReadPngForMod } from '@wailsjs/go/main/App'
import { EventsOn, EventsOff } from '@wailsjs/runtime'

const ipcUtils = {
  readPngForMod: (filePath: string): Promise<string[]> =>
    ReadPngForMod(filePath),

  onDownloadProgress: (callback) => {
    EventsOn('download:progress', callback)
    return () => EventsOff('download:progress')
  },
  // ...
}
```

## 数据流

### 1. 用户操作流程

```
用户操作 (UI)
    ↓
React 组件处理
    ↓
Zustand Store 更新状态
    ↓
调用 ipcUtils.xxx (兼容层)
    ↓
wailsjs 生成的绑定函数
    ↓
Go App 绑定方法处理
    ↓
调用 internal/ 包完成 I/O 或网络操作
    ↓
返回 Promise 结果
    ↓
更新 Store / 显示结果
```

### 2. 异步事件流程（下载 / 爬虫）

```
前端调用 ipcUtils.triggerDownload / runSideloader
    ↓
Go 后端启动异步任务（Goroutine）
    ↓
任务执行中通过 EventsEmit 推送进度
    ↓
前端 EventsOn 监听 download:progress / sideloader:progress
    ↓
更新 Store 显示进度
    ↓
任务完成推送 download:complete / sideloader:complete
```

## 设计原则

### 1. 关注点分离

- **前端** 专注 UI 和交互
- **Go 后端** 专注系统集成和协调
- **internal 包** 专注高性能计算和 I/O

### 2. 后端内聚

Go 后端代码直接编译进应用：
- 无外部进程依赖，无需回退方案
- 同一套代码同时支撑应用内调用与独立 CLI（`wails/cmd/`）
- 对用户透明，无需额外配置

### 3. 类型安全

- 全项目使用 TypeScript
- 共享类型定义在 `wails/frontend/src/shared/`
- Wails 自动生成绑定代码的 TypeScript 类型（`wailsjs/go/models.ts`）

### 4. 错误处理

```typescript
// 多层错误处理
try {
  // 调用 Go 绑定方法
  return await ipcUtils.someOperation()
} catch (e) {
  // 显示错误提示
  message.error(`操作失败: ${e}`)
  throw e
}
```

## 性能考虑

### 1. 并发处理

- Go 后端使用 Goroutine 实现并发（爬虫 10 并发、批量解析并发）
- 批量操作分批处理，避免阻塞

### 2. 虚拟滚动

- 大数据列表使用虚拟滚动
- 只渲染可见区域内容

### 3. 懒加载

- 图片懒加载
- 组件懒加载（React.lazy）

### 4. 缓存策略

- 文件扫描结果缓存
- Mod 数据本地存储（`localMods.json`）

## 安全考虑

### 1. 能力收敛

- 前端无法直接访问系统 API
- 所有系统操作通过 Wails 绑定收敛到 App 导出方法

### 2. 输入验证

- 所有用户输入都经过验证
- 文件路径安全检查

### 3. 资源限制

- 爬虫使用信号量限制并发
- 下载使用流式处理，避免内存溢出

## 扩展性设计

### 添加新功能

1. **添加新页面**
   - 创建页面组件
   - 添加路由
   - 更新导航

2. **添加新后端接口**
   - 在 `wails/app.go` 的 `App` 上添加导出方法
   - 运行 `wails dev`/`wails build` 自动重新生成前端绑定
   - 在 `ipcUtils.ts` 中封装兼容接口
   - 如需异步通知，使用 `EventsEmit`/`EventsOn`

3. **添加新 Go 内部包**
   - 在 `wails/internal/` 下创建包
   - 在 `app.go` 中引用并封装为绑定方法
   - 如需独立命令行工具，在 `wails/cmd/` 下添加入口
