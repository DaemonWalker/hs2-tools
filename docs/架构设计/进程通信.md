# 进程通信

本文档介绍 HS2-Tools 的前后端通信机制。

## 通信概览

迁移到 Wails 后，应用不再有 Electron 的「主进程 / 渲染进程」之分，Go 后端与 WebView 前端运行在同一应用内。Wails 提供两种通信方式：

| 方式 | 方向 | 用途 |
|------|------|------|
| `Bind` 绑定方法调用 | 前端→Go | 请求/响应（Promise） |
| `EventsEmit` / `EventsOn` | Go→前端 | 异步事件推送（进度、完成通知） |

HS2-Tools 以绑定方法调用为主，长耗时任务（下载、爬虫）配合事件推送进度。

## 通信架构

```
┌─────────────────────────────────────────────────────────────────┐
│                        Wails 通信架构                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   前端 (React)                        Go 后端                    │
│  ┌─────────────────┐              ┌─────────────────┐          │
│  │   UI Component  │              │    App 结构体   │          │
│  │                 │              │                 │          │
│  │  ipcUtils.xxx() │ ──调用────→  │  导出方法        │          │
│  │  (兼容层)        │              │  (Bind)         │          │
│  │                 │ ←─Promise──  │   return data   │          │
│  └─────────────────┘              └────────┬────────┘          │
│         │ wailsjs/go/main/App              │                    │
│         │ (生成的绑定)                      ↓                    │
│         │                           ┌─────────────────┐        │
│         │                           │  internal/ 包   │        │
│         │                           │  scanner 等     │        │
│         │                           └─────────────────┘        │
│         │                                                      │
│  ┌─────────────────┐              ┌─────────────────┐          │
│  │   EventsOn()    │ ←─EventsEmit─│  wailsRuntime   │          │
│  │  (事件监听)     │              │  .EventsEmit()  │          │
│  └─────────────────┘              └─────────────────┘          │
│   (下载/爬虫进度通知)                (异步任务主动推送)           │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 绑定方法

### 工作原理

`wails/app.go` 中的 `App` 结构体通过 `main.go` 的 `Bind` 选项暴露给前端：

```go
// wails/main.go
err := wails.Run(&options.App{
    // ...
    Bind: []interface{}{
        app,
    },
})
```

`App` 上的所有**导出方法**（首字母大写）自动成为前端可调用的接口。Wails 在 `wails dev` / `wails build` 时自动生成前端绑定代码（`wails/frontend/wailsjs/go/main/App.js` 及 `App.d.ts`），前端以 Promise 方式调用：

```typescript
import { ReadPngForMod } from '@wailsjs/go/main/App'

const mods = await ReadPngForMod('/path/to/card.png')
```

Go 方法返回的第二个值若为 `error`，前端 Promise 会在出错时 reject。

### 绑定方法清单

`App` 约 30 个导出方法，按功能分组（详见 [../API参考/后端接口](../API参考/后端接口.md)）：

| 分组 | 方法 |
|------|------|
| 文件操作 | `ReadDir`、`GetAllFiles`、`MoveFile`、`CheckTargetDir`、`FileExists`、`DirExists` |
| PNG/zipmod 解析 | `ReadPngForMod`、`ReadAllCharaNames`、`ReadPngForShow`、`ReadZipMod`、`ReadZipModBatch`、`ReadPngModsBatch`、`ReadPngNamesBatch`、`ReadPngImagesBatch`、`ReadPngPageDataBatch` |
| 路径选择 | `SelectPath`、`OpenFileSelector` |
| 设置持久化 | `LoadSettings`、`SaveSettings`、`LoadLocalMods`、`SaveLocalMods` |
| 下载 | `TriggerDownload`、`CancelDownload`、`GetDownloaderStatus` |
| 爬虫 | `RunSideloader`、`StopSideloader`、`IsSideloaderRunning`、`GetSideloaderStatus`、`InitSideload` |
| 系统 | `SetProxy`、`DisableWindowsSleep`、`EnableWindowsSleep`、`LaunchGame`、`LaunchStudio`、`OpenInFolder`、`Log`、`Ping`、`GetScannerStatus` |

## 事件机制

### 事件命名约定

Wails 事件使用 `:` 分隔的命名风格（替代旧 Electron 的 kebab-case）：

| 事件 | 含义 |
|------|------|
| `download:progress` | 下载进度更新 |
| `download:complete` | 下载完成/失败/取消 |
| `sideloader:progress` | 爬虫进度更新 |
| `sideloader:complete` | 爬虫完成/失败/停止 |

### Go 端推送

长耗时任务在 Goroutine 中执行，通过 `wailsRuntime.EventsEmit` 推送进度：

```go
// wails/app.go
import wailsRuntime "github.com/wailsapp/wails/v2/pkg/runtime"

wailsRuntime.EventsEmit(a.ctx, "download:progress", DownloadProgressEvent{
    GUID:       guid,
    Type:       "progress",
    Downloaded: p.Downloaded,
    Total:      p.Total,
    Speed:      p.Speed,
    Percent:    p.Percent,
})

// 任务结束时
wailsRuntime.EventsEmit(a.ctx, "download:complete", DownloadCompleteEvent{
    GUID:    guid,
    Success: true,
})
```

### 前端监听

```typescript
import { EventsOn, EventsOff } from '@wailsjs/runtime'

// 监听
EventsOn('download:progress', (data) => {
  console.log(`${data.guid}: ${data.percent}%`)
})

// 取消监听
EventsOff('download:progress')
```

### 事件数据类型

```typescript
// 下载进度
type DownloadProgressEvent = {
  guid: string
  type: 'progress' | 'complete' | 'error' | 'info'
  downloaded?: number
  total?: number
  speed?: number
  percent?: number
  path?: string
  message?: string
}

// 下载完成
type DownloadCompleteEvent = {
  guid: string
  success: boolean
  message?: string
}

// 爬虫进度
type SideloaderProgressEvent = {
  type: 'info' | 'progress' | 'complete' | 'error'
  message?: string
  current?: number
  total?: number
  percent?: number
}

// 爬虫完成
type SideloaderCompleteEvent = {
  success: boolean
  data?: SideloadModel
  error?: string
}
```

## ipcUtils 兼容层

### 设计目的

迁移自 Electron 时，为减少对前端业务代码的改动，`wails/frontend/src/logic/ipcUtils.ts` 将生成的绑定函数和事件 API 封装成与旧 `window.api`（ipcRenderer）同形的接口：

- 方法名保持 camelCase（如 `readPngForMod` 对应 Go 的 `ReadPngForMod`）
- 事件监听封装为 `onXxx(callback)` 形式，返回取消订阅函数
- 在兼容层中补充与业务相关的逻辑（如下载目录拼接、路径处理）

### 实现示例

```typescript
// wails/frontend/src/logic/ipcUtils.ts
import {
  ReadPngForMod, TriggerDownload, CancelDownload, /* ... */
} from '@wailsjs/go/main/App'
import { EventsOn, EventsOff } from '@wailsjs/runtime'

const ipcUtils = {
  // 绑定方法封装
  readPngForMod: (filePath: string): Promise<string[]> =>
    ReadPngForMod(filePath),

  // 含业务逻辑的封装：拼接下载目录
  triggerDownload: (info: { name: string; url: string }): Promise<void> => {
    const basePath = useSettingStore.getState().modsPath()!
    const downloadDir = `${basePath}/hs2-tool-download`
    return TriggerDownload({ name: info.name, url: info.url, dir: downloadDir })
  },

  // 事件监听封装：返回取消订阅函数
  onDownloadProgress: (callback: (event: DownloadProgressEvent) => void): (() => void) => {
    EventsOn('download:progress', callback)
    return () => EventsOff('download:progress')
  },
  onDownloadComplete: (callback: (event: DownloadCompleteEvent) => void): (() => void) => {
    EventsOn('download:complete', callback)
    return () => EventsOff('download:complete')
  },
  // ...
}

export default ipcUtils
```

### 业务代码使用

```typescript
import ipcUtils from '../logic/ipcUtils'

// 调用后端方法
const mods = await ipcUtils.readPngForMod('/path/to/card.png')

// 监听事件（useEffect 中记得取消订阅）
useEffect(() => {
  const unsubscribe = ipcUtils.onDownloadProgress((data) => {
    console.log('Progress:', data.percent)
  })
  return unsubscribe
}, [])
```

## 错误处理

### 错误传播

```
internal 包 → App 绑定方法 → 绑定函数 → 前端业务代码
    ↓              ↓              ↓
  error        return err    Promise reject
```

### 错误处理示例

```typescript
// 前端层
try {
  const mods = await ipcUtils.readPngForMod(path)
} catch (e) {
  message.error(`操作失败: ${e}`)
}
```

```go
// Go 层：error 作为返回值，自动转为前端 Promise 的 reject
func (a *App) ReadPngForMod(path string) ([]string, error) {
    return scanner.ReadPngMods(path)
}
```

## 性能优化

### 1. 批量操作

```typescript
// ✅ 批量操作（一次调用）
const results = await ipcUtils.readPngModsBatch(paths)

// ❌ 避免循环调用（多次桥接开销）
for (const path of paths) {
  await ipcUtils.readPngForMod(path) // 效率低！
}
```

### 2. 并发控制

批量操作在 Go 端内部控制并发（信号量 + Goroutine）：

```go
// wails/internal/scanner 中的批量处理
func ReadPngModsBatch(paths []string, concurrency int) ([]PngModResult, error) {
    sem := make(chan struct{}, concurrency)
    var wg sync.WaitGroup

    for _, path := range paths {
        wg.Add(1)
        sem <- struct{}{}
        go func(p string) {
            defer wg.Done()
            defer func() { <-sem }()
            // 处理单个文件
        }(path)
    }

    wg.Wait()
    // ...
}
```

## 安全注意事项

1. **验证路径** - 防止目录遍历攻击
2. **限制参数** - 检查参数范围和类型
3. **超时处理** - 防止长时间阻塞（下载/爬虫均支持 context 取消）
4. **错误信息** - 不向用户暴露敏感信息
