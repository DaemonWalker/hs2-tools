# 快速开始

## 环境要求

- Windows 10/11（x64）
- 开发：.NET 10 SDK **10.0.400 或更新补丁**（xUnit v3 使用原生 Microsoft.Testing.Platform v2）
- 运行发布产物：无需安装 .NET（自包含单文件）

## 构建与运行

```bash
dotnet build                          # 构建
dotnet run --project HS2Tools         # 开发模式启动应用
```

## 测试

```bash
dotnet test
```

测试项目使用 xUnit v3 和原生 Microsoft.Testing.Platform；`global.json` 已选择测试运行器并要求最低 SDK 版本。需要覆盖率时使用微软官方扩展：

```bash
dotnet test --coverage --coverage-output-format cobertura
```

当前 361 项测试（353 通过 / 8 跳过）。默认全部通过的为单元/集成测试；以下基准与对照测试**默认跳过**，设置环境变量后运行（KK/KKS 的真实目录同样可用这些变量验证）：

| 环境变量 | 作用 |
|---|---|
| `HS2_REAL_CARD_DIRS` | 真实卡片目录（分号分隔），结构化解析逐卡验证并输出与旧字节扫描的差异统计 |
| `HS2_REAL_MODS_DIR` | 真实 mods 目录，zipmod 全量扫描基准 |
| `HS2_REAL_GAME_DIR` | 真实游戏目录，三阶段扫描基准 |
| `HS2TOOLS_REAL_CRAWL=1` | 真实站点爬虫对照（约 30 分钟） |

示例：

```bash
HS2_REAL_GAME_DIR='F:\game\HS2V24' dotnet test --filter "FullyQualifiedName~Scan_RealGameDir"
```

## 打包发布

```bash
dotnet publish HS2Tools/HS2Tools.csproj -c Release -r win-x64 \
  --self-contained -p:PublishSingleFile=true -o publish
```

产物：`publish/HS2Tools.exe`（单文件自包含，约 160MB）。内嵌 sideload.zip 数据库（仅 HS2 库）随单文件分发，首次运行无网络也可用；KK/KKS 的 kkec 库无内嵌回退，需先在应用内运行一次爬虫更新。

### GitHub Release

在 GitHub 仓库的 **Actions → Release → Run workflow** 中手动启动发布，输入前三段版本号 `base_version`（例如 `1.0.0`）。工作流使用运行编号作为 Build 号，生成四段版本号 `主版本号.次版本号.修订号.Build号`（例如 `1.0.0.42`），每段必须在 0 到 65534 之间。

工作流会依次运行测试、以 .NET 10 构建自包含的 `win-x64` 产物、写入 exe 文件版本、打包完整发布目录并生成 SHA-256 校验文件，最后创建同名 Git 标签和 GitHub Release。测试失败、版本格式错误或标签已存在时不会发布。

工作流还会在每天北京时间 02:17（UTC 18:17）自动检查默认分支：以最新四段版本标签为基准，没有新提交时跳过构建与发布；有新提交时将修订号加 1，例如从 `1.0.0.42` 升级为 `1.0.1.43`，第四段仍取工作流运行编号。首次发布必须先通过手动流程创建首个版本标签。GitHub 定时任务可能延迟执行。

发布产物：

- `HS2Tools-v1.0.0.42-win-x64.zip`
- `HS2Tools-v1.0.0.42-win-x64.zip.sha256`

Release 标题为 `HS2 Tools v1.0.0.42`，发布说明由 GitHub 自动生成。每次手动运行会取得新的 Build 号；重新运行同一次工作流会复用 Build 号，若对应标签已存在则停止。

## 首次使用

1. 启动 `HS2Tools.exe`
2. 顶部切换器选择游戏（HS2 / 恋活 KK / 恋活 Sunshine KKS），首页「游戏路径」选择对应游戏目录（按该游戏 exe 校验，绿点为有效）；KK/KKS 的 exe 名按常见安装版填写，若校验不通过请反馈真实 exe 名
3. 点「数据分析」执行三阶段扫描（Mod → 场景 → 角色卡）
4. 之后即可浏览角色卡/场景、查看缺失 Mod、一键补全

## 数据位置

存储在数据目录（绿色版：程序所在目录下 `data/`；无写权限时回退 `%AppData%/hs2-tools/`，首次启动自动迁移旧配置）：

| 文件 | 内容 |
|---|---|
| `settings.json` | 统一配置（当前游戏 + 各游戏独立的游戏路径/收藏/本地 Mod 库/使用统计、代理、防休眠）；旧版单游戏配置自动迁移 |
| `analysis-cache.db` | Mod/卡片增量分析缓存，以及 Sideload 索引、Last modified 和扫描记录（SQLite，按数据源隔离）；旧 `sideload*.json` 自动迁入并保留 `.migrated` 备份。删除后分析缓存可重建，但 Sideload 用户索引需重新更新或从内嵌库回退 |
| `error.log` | 错误日志（追加写入，排障先看这里） |
