# 开发规范

## C# 代码规范

- **MVVM 分层**：Views 只做视图与绑定；逻辑在 ViewModel；状态与 IO 在服务层单例。窗口之间不直接引用，跨窗体通信走服务事件。
- **服务层与 UI 解耦**：`Services/` 不依赖 WPF（ErrorLog 除外的基础设施保持纯 C#），可独立单测。
- **错误处理**：
  - 不允许"静默吞错"——跳过的条目、失败的任务至少 `ErrorLog.Log(...)` 记一条；
  - 用户可见的失败给出统一格式提示："XX失败：原因"；
  - 后台线程（Timer 回调、任务续体）的异常必须就地捕获——逃逸即崩进程，`DispatcherUnhandledException` 管不到非 UI 线程。
- **长任务纪律**：CanExecute 门控 + 标志位双保险防重入；取消一律 `CancellationTokenSource`；进度经 `IProgress<T>` 或事件 + `UiDispatch` 封送。
- **UI 样式**：颜色/画刷一律 `DynamicResource` 引用 `Themes/Theme.xaml`，不留硬编码色值；空状态/无图占位为每个列表与图片区的必备项。
- **注释**：中文，写明"为什么"（尤其行为保真相关的字节级 hack，须注明对应旧版行为）。

## 测试规范

- **夹具程序化合成**：PNG 标记字节、MessagePack 合成的结构化卡片/场景数据区（`TestAssets.BuildCharaDataRegion` 等）、Store/Deflate/脏 manifest zipmod、autoindex HTML、`HttpListener` 内存测试服务器（Range/HEAD/慢速流式）——不提交大文件。
- **环境隔离**：测试用 `ConfigService`/数据库一律指向临时目录；`ErrorLog` 经 `TestAssets` 静态构造统一重定向，不污染真实数据目录。
- **真实环境基准**默认跳过，用 `Skip.If(环境变量缺失)` 门控（见 [快速开始](./快速开始.md#测试)）。
- 解析器行为改动须配字节级回归用例（边界：EOCD comment、ZIP64、IEND 截断、控制字符、非 ASCII、代理对）。卡片/场景解析以 IllusionModdingAPI/BepisPlugins 为基准做结构化解析（`CharaCardParser`，KK/KKS 格式参照 kkloader），旧字节扫描仅作数据区内回退路径，回退契约（`SearchBuffer_*` 用例）不得破坏。

## 贡献指南

1. 提交前：`dotnet build` 零警告、`dotnet test` 全绿。
2. 改动行为时同步更新 `docs/` 对应文档。
3. 提交信息：中文，简要说明"做了什么 + 为什么"，参照 git 历史风格。
4. 发布产物（`publish/`）、构建中间产物（`bin/`、`obj/`）不进仓库。
