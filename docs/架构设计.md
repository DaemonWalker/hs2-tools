# 架构设计

## 整体架构

单进程 WPF 应用，经典三层：**Views → ViewModels → Services**。无 IPC、无前端运行时，ViewModel 直接 `await` 服务。

```
Views (8 Window)  ──Binding──▶  ViewModels  ──调用──▶  Services (单例)
     ▲                                ▲                      │
     └────────── 服务事件（C# event / IProgress<T>）──────────┘
```

原则：**状态全部下沉到服务层单例，Window 只是视图**。跨窗体通信走服务事件，窗口之间不直接引用。

## 服务层（`HS2Tools/Services/`）

| 服务 | 职责 |
|---|---|
| `ConfigService` | 统一配置读写（settings.json），改动发 `Changed` 事件、500ms 防抖落盘；`CurrentProfile` 取当前游戏档案，派生路径按当前游戏求值；旧版单游戏配置加载时自动迁移；写盘失败记日志并保持脏标记重试，永不抛出 |
| `ScannerService` | 目录扫描（子串排除、扩展名不敏感）、卡片/场景解析入口（名称/Mod GUID/缩略图）、zipmod manifest 解析、批量并行解析；解析失败回退旧字节扫描（仅数据区，HS2 与 KK/KKS 两套字段名都认）。数据区起点走 PNG chunk 步行定位真 IEND（追加数据可能含 "IEND" 字节，反向字节扫描仅作回退） |
| `CharaCardParser` | 卡片/场景数据区结构化解析（BlockHeader + KKEx/UAR，MessagePack-CSharp 底层 Reader 步行），基准 IllusionModdingAPI/BepisPlugins；按卡头标记自动识别游戏格式（HS2 `【AIS_Chara】` 与 KK/KKS `【KoiKatuChara】` 都认，不依赖当前游戏），角色名按各游戏 Parameter 字段键拼接；blob 信封按 `GameProfile.CharaBlobHasFacePng` 分两种（KK/KKS 在 version 后多一个 facePng，且无 lang/userID/dataID） |
| `DownloaderService` | 断点续传下载（206/200 分支）、代理（含认证）、进度节流 |
| `DownloadManager` | 全局下载任务表 + 进度/完成事件；同名任务重复触发拒绝；窗口关闭不中断下载；下载 base URL 由调用方按当前游戏档案传入 |
| `SideloaderService` | BetterRepack 爬虫：HTML 目录解析（HtmlAgilityPack）+ 远程 ZIP 中央目录解析（渐进式尾部抓取，无需整包下载）；从起点 URL 递归下钻全部子目录，起点取 `GameProfiles` 的 `SideloadBaseUrl`；两级信号量并发；可重入 Run |
| `SideloadDatabaseService` | 按数据源分库（`sideload-{sourceId}.json`，KK/KKS 共享 kkec 库）；加载顺序：用户库 > 内嵌库（仅 hs2 有内嵌库）；随游戏切换触发 Changed |
| `GameLauncherService` | 启动游戏/工作室、`explorer /select,` 打开所在文件夹、`SetThreadExecutionState` 防休眠 |
| `ErrorLog` | 统一错误日志（error.log，追加写入，永不抛出） |

`ServiceContainer` 在 `App.OnStartup` 创建全部单例；Sideloader 每次运行经工厂新建（代理与当前游戏的 base URL 即时生效）。

## 多游戏抽象（`HS2Tools/Models/GameProfile.cs`）

支持 HS2 / 恋活（KK）/ 恋活 Sunshine（KKS）三款游戏。游戏特定知识（exe 名、目录相对路径、卡片标记字节、Parameter 名字段键、sideload 数据源与 base URL）全部收编进 `GameProfile` 描述符，`GameProfiles` 静态注册表提供三条档案（`hs2`/`kk`/`kks`），未知 ID 回退 HS2。KK 与 KKS 卡片格式相同（同为【KoiKatuChara】+ KKEx），差异仅在 exe/目录；KK/KKS 的 exe 名按常见安装版填写，待真实环境验证。

- 服务层不直接写死游戏知识：`ConfigService.CurrentProfile` 是当前游戏的唯一入口，派生路径、路径校验、启动 exe、爬虫起点/下载 base URL 都经它求值。
- 卡片解析按卡头标记自动识别格式（两套标记都在格式表里），与"当前游戏"解耦——任何游戏的卡片都能被解析。
- 切换游戏 = 改 `settings.json` 的 `currentGame`；各窗口经 `Config.Changed` + 游戏 ID 比较门控自动重扫（收藏等其他配置变化不触发重扫）；扫描/爬虫运行中禁止切换。

## 多窗体架构

- **每页一个独立 Window**，主窗口常驻做首页与导航。
- `WindowManager`：窗口只创建一次；导航 = `Show()` + `Activate()`；用户点关闭 = 取消 Closing + `Hide()`——**保持状态**（滚动位置、筛选、已加载缩略图）。
- MainWindow 真正关闭时才退出应用（`ShutdownMode="OnMainWindowClose"`）。
- ViewModel 与窗口同寿（单例），**永久订阅**服务事件；事件经 `UiDispatch` 封送到 UI 线程，窗口隐藏期间状态照常更新，重新显示即见最新。

## 数据存储

数据目录（`ConfigService.DefaultConfigDir`）：绿色版优先程序所在目录下 `data/`，无写权限（如 Program Files）回退 `%AppData%/hs2-tools/`；首次启动时旧 `%AppData%` 配置自动迁移到安装目录。

```json
// settings.json（强类型 AppSettings；游戏路径/收藏/本地 Mod 缓存/使用统计按游戏隔离在 games 下）
{
  "currentGame": "hs2",
  "games": {
    "hs2": {
      "gamePath": "…",
      "favorites": ["…卡片完整路径…"],
      "localMods": { "guid": { "name": "…", "version": "…", "path": "…" } },
      "modUsage": { "guid": 3 }
    },
    "kk":  { "gamePath": "…", "favorites": [], "localMods": {}, "modUsage": {} }
  },
  "proxy": { "uri": "http://127.0.0.1:7890", "username": "", "password": "" },
  "preventSleep": false
}
```

旧版单游戏 schema（顶层 `gamePath`/`favorites`/`localMods`/`modUsage`）加载时自动迁移为 `games["hs2"]` 并立即落盘。

- `sideload-{数据源}.json`：爬虫更新后的数据库（guid → 相对 URL），按 GameProfile.SideloadSourceId 分库（如 `sideload-hs2.json` / `sideload-kkec.json`）；hs2 不存在用户库时回退程序集内嵌的 sideload.zip，kkec 无内嵌库回退空库（需先运行爬虫更新）。旧版 `sideload.json` 启动时自动迁移为 hs2 库。
- `error.log`：错误日志。全局兜底 `App.DispatcherUnhandledException`（记日志 + MessageBox）；各失败路径在提示用户的同时至少记一条日志。

## 异步与线程模型

- 所有 IO/网络/解析走 `async/await`；CPU 密集批量解析用 `Parallel.ForEachAsync`（并发度：文本 8 / 图像 4 / zipmod 4 / 爬虫 mod 10、目录 3）。
- 进度上报：`IProgress<T>` 或服务事件（订阅方经 `UiDispatch` 封送 UI 线程）。
- 取消一律 `CancellationTokenSource`；长任务（扫描/补全/爬虫/整理）后台执行 + **防重入**（CanExecute 门控 + 标志位双保险）。
- 网络细节：每个 `HttpRequestMessage` 显式 `Version = 2.0, VersionPolicy = RequestVersionOrLower`；未配置代理时显式 `UseProxy = false`（不走系统代理）；Range 请求被 200 应答时丢弃该块（防代理干预下内存爆炸）。

## 关键组件

| 组件 | 说明 |
|---|---|
| `CardGridControl` | 卡片虚拟化网格：全量路径 → 过滤/排序 → 分批 24 解析（一次读盘同时拿名称+缩略图），滚动加载；收藏/搜索/zh-CN 排序 |
| `VirtualizingWrapPanel` | 自实现固定项尺寸虚拟化面板（WPF 无内置），约 200 行 |
| `ThumbnailCache` | 缩略图 LRU 缓存（500 张）控内存 |
| `CardDetailPanel` | 角色/场景共用详情：大图、Mod 依赖列表、单项/一键下载、真实文件信息、打开所在文件夹 |
| `ZipRemoteReader` | 远程 ZIP 中央目录解析：渐进式尾部抓取 + EOCD 定位 + 裸 DEFLATE 解压（上限 16MB 防炸弹） |

## 主题

单主题。`Themes/Theme.xaml` 集中定义颜色/画刷，控件一律 `DynamicResource` 引用，不留硬编码色值——为后期多主题留扩展口。
