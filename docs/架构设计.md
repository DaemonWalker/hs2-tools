# 架构设计

## 整体架构

单进程 WPF 应用，经典三层：**Views → ViewModels → Services**。无 IPC、无前端运行时，ViewModel 直接 `await` 服务。

```
MainWindow + 8 个缓存页面  ──Binding──▶  ViewModels  ──调用──▶  Services (单例)
          ▲                                  ▲                      │
          └────────── 服务事件（C# event / IProgress<T>）──────────┘
```

原则：**状态全部下沉到服务层单例，View 只负责展示与绑定**。页面之间不直接引用，跨页通信走服务事件；主壳持有全局游戏切换与工作台共用的 `MainWindowViewModel`。

## 服务层（`HS2Tools/Services/`）

| 服务 | 职责 |
|---|---|
| `ConfigService` | 统一配置读写（settings.json），改动发 `Changed` 事件、500ms 防抖落盘；`CurrentProfile` 取当前游戏档案，派生路径按当前游戏求值；旧版单游戏配置加载时自动迁移；写盘失败记日志并保持脏标记重试，永不抛出 |
| `ScannerService` | 目录扫描（子串排除、扩展名不敏感）、卡片/场景解析入口（一次读盘返回名称/Mod GUID/图像与文件指纹）、zipmod manifest 解析、批量并行解析与缓存回调；解析失败回退旧字节扫描（仅数据区，HS2 与 KK/KKS 两套字段名都认），回退扫描使用 `ReadOnlySpan<byte>` 避免数组切片复制；zipmod 文件与 manifest 读取使用 .NET 10 异步 ZIP API。Mod GUID 统一规范化（保留 Unicode、移除控制字符并 Trim），与站点索引匹配口径一致。数据区起点走 PNG chunk 步行定位真 IEND（追加数据可能含 "IEND" 字节，反向字节扫描仅作回退） |
| `CharaCardParser` | 卡片/场景数据区结构化解析（BlockHeader + KKEx/UAR，MessagePack-CSharp 底层 Reader 步行），基准 IllusionModdingAPI/BepisPlugins；按卡头标记自动识别游戏格式（HS2 `【AIS_Chara】` 与 KK/KKS `【KoiKatuChara】` 都认，不依赖当前游戏），角色名按各游戏 Parameter 字段键拼接；blob 信封按 `GameProfile.CharaBlobHasFacePng` 分两种（KK/KKS 在 version 后多一个 facePng，且无 lang/userID/dataID）；UAR 数据键角色/坐标卡为 `info`，工作室场景为 `itemInfo`/`patternInfo`，地图 mod GUID 直接挂在 `mapInfoGUID` 字符串值上（真实场景卡实测）；`ReadOnlyMemory` 块切片避免额外复制，`OrderedDictionary` 保序去重 |
| `AnalysisCacheService` | SQLite 增量缓存（`analysis-cache.db`）：按游戏与 mods/unusedmods/scene/chara 分域，以路径 + 文件大小 + 修改时间判断有效性，缓存版本变化时清空重建；批量扫描事务写回，单卡查看按需更新；不可用则记日志并回退完整解析 |
| `DownloaderService` | 断点续传下载（206/200 分支），续传返回 416 时自动从头重试一次；代理（含认证）、进度节流；异步文件流与 `ArrayPool` 复用下载缓冲区 |
| `DownloadManager` | 全局串行下载队列 + 任务表 + 进度/完成事件；新任务立即以等待中入列，同名等待/下载中任务重复触发拒绝；窗口关闭不中断下载；下载 base URL 由调用方按当前游戏档案传入 |
| `SideloaderService` | BetterRepack 爬虫：HTML 目录解析（HtmlAgilityPack）+ 远程 ZIP 中央目录解析（渐进式尾部抓取，无需整包下载）；从起点 URL 遍历全部子目录，起点取 `GameProfiles` 的 `SideloadBaseUrl`；单目录生产者 + Channel + 10 个异步 Mod 消费者；可重入 Run |
| `SideloadDatabaseService` | 在 `analysis-cache.db` 按 source_id 分库（KK/KKS 共享 kkec）；自动迁移旧 JSON 并保留 `.migrated` 备份；加载顺序：SQLite 用户库 > 内嵌库（仅 hs2 有内嵌库）；随游戏切换触发 Changed |
| `GameLauncherService` | 启动游戏/工作室、`explorer /select,` 打开所在文件夹、`SetThreadExecutionState` 防休眠 |
| `ErrorLog` | 统一错误日志（error.log，追加写入，永不抛出） |

`ServiceContainer` 在 `App.OnStartup` 创建全部单例；Sideloader 每次运行经工厂新建（代理与当前游戏的 base URL 即时生效）。

## 多游戏抽象（`HS2Tools/Models/GameProfile.cs`）

支持 HS2 / 恋活（KK）/ 恋活 Sunshine（KKS）三款游戏。游戏特定知识（exe 名、目录相对路径、卡片标记字节、Parameter 名字段键、sideload 数据源与 base URL）全部收编进 `GameProfile` 描述符，`GameProfiles` 静态注册表提供三条档案（`hs2`/`kk`/`kks`），未知 ID 回退 HS2。KK 与 KKS 卡片格式相同（同为【KoiKatuChara】+ KKEx），差异仅在 exe/目录；KK/KKS 的 exe 名按常见安装版填写，待真实环境验证。

- 服务层不直接写死游戏知识：`ConfigService.CurrentProfile` 是当前游戏的唯一入口，派生路径、路径校验、启动 exe、爬虫起点/下载 base URL 都经它求值。
- 卡片解析按卡头标记自动识别格式（两套标记都在格式表里），与"当前游戏"解耦——任何游戏的卡片都能被解析。
- 切换游戏 = 改 `settings.json` 的 `currentGame`；侧栏底部下拉框在所有页面可见，各页面经 `Config.Changed` + 游戏 ID 比较门控自动重扫（收藏等其他配置变化不触发重扫）；扫描/爬虫运行中禁止切换。

## 单窗口导航架构

- **MainWindow 是唯一 Window**，包含全局游戏切换器、左侧导航和页面内容宿主；工作台与 7 个功能页均为 `UserControl`。
- `PageManager`：每个页面只创建一次，导航仅替换内容宿主——**保持页面实例、滚动位置、筛选条件和已加载缩略图**。
- MainWindow 真正关闭时才退出应用（`ShutdownMode="OnMainWindowClose"`）；切换页面不中断下载、扫描或爬虫。
- `MainWindowViewModel` 归主壳持有，工作台继承同一实例；其他 ViewModel 与页面同寿并**永久订阅**服务事件，页面隐藏期间状态照常更新。

## 数据存储

数据目录（`ConfigService.DefaultConfigDir`）：绿色版优先程序所在目录下 `data/`，无写权限（如 Program Files）回退 `%AppData%/hs2-tools/`；首次启动时旧 `%AppData%` 配置自动迁移到安装目录。

```json
// settings.json（强类型 AppSettings；游戏路径/收藏/本地 Mod 缓存/使用统计按游戏隔离在 games 下）
{
  "currentGame": "hs2",
  "games": {
    "hs2": {
      "gamePath": "…",
      "favorites": ["…卡片完整路径…"],
      "localMods": { "guid": { "name": "…", "version": "…", "path": "…" } },
      "modUsage": { "guid": 3 }
    },
    "kk":  { "gamePath": "…", "favorites": [], "localMods": {}, "modUsage": {} }
  },
  "proxy": { "uri": "http://127.0.0.1:7890", "username": "", "password": "" },
  "preventSleep": false
}
```

旧版单游戏 schema（顶层 `gamePath`/`favorites`/`localMods`/`modUsage`）加载时自动迁移为 `games["hs2"]` 并立即落盘。

- `analysis-cache.db`：SQLite 分析缓存与 Sideload 本地记录。`card_cache` / `zipmod_cache` 以 `game_id + scope + path` 为主键，文件大小与修改时间不匹配即重新解析，缓存版本变化仅清空这两类分析表。`sideload_sources` / `sideload_entries` 按 source_id 保存 guid、相对 URL、Last modified 与 last-seen，`sideload_scan_meta` 保存扫描结果；hs2 无用户记录时回退内嵌 sideload.zip，kkec 回退空库。旧版 `sideload*.json` 与 meta 首启自动迁移并保留 `.migrated` 备份。WAL 模式，批量替换与 Sideload 更新走事务；不替代 settings.json 中去重/整理/清理所需的完整条目与统计。
- `error.log`：错误日志。全局兜底 `App.DispatcherUnhandledException`（记日志 + MessageBox）；各失败路径在提示用户的同时至少记一条日志。

## 异步与线程模型

- 所有 IO/网络/解析走 `async/await`；CPU 密集批量解析用 `Parallel.ForEachAsync`（并发度：文本 8 / 图像 4 / zipmod 4）；Sideload 爬虫为单目录生产者 + 10 个异步 Mod 消费者。
- 进度上报：`IProgress<T>` 或服务事件（订阅方经 `UiDispatch` 封送 UI 线程）。
- 取消一律 `CancellationTokenSource`；长任务（扫描/补全/爬虫/整理/清理）后台执行 + **防重入**（CanExecute 门控 + 标志位双保险）。
- 网络细节：每个 `HttpRequestMessage` 显式 `Version = 2.0, VersionPolicy = RequestVersionOrLower`；未配置代理时显式 `UseProxy = false`（不走系统代理）；Range 请求被 200 应答时丢弃该块（防代理干预下内存爆炸）。

## 关键组件

| 组件 | 说明 |
|---|---|
| `CardGridControl` | 卡片虚拟化网格：当前目录直接卡片路径 → 过滤/排序 → 分批 24 解析（一次读盘同时拿名称+Mod+PNG 字节），滚动加载；搜索/排序保留图像缓存，显式刷新失效；角色卡/场景页左侧目录树显示全部目录（含空目录），默认根目录且不递归混入子目录卡片 |
| `VirtualizingWrapPanel` | 自实现固定项尺寸虚拟化面板（WPF 无内置），约 200 行 |
| `ThumbnailCache` | 缩略图 LRU 缓存（500 张）控内存；PNG 字节直接后台按显示宽度与 DPI 解码、Freeze 后回 UI，不再使用 Base64 |
| `CardDetailPanel` | 角色/场景共用详情：一次读盘取得大图、名称与 Mod 依赖，单项/一键下载、真实文件信息、打开所在文件夹 |
| `ZipRemoteReader` | 远程 ZIP 中央目录解析：渐进式尾部抓取 + EOCD 定位 + 裸 DEFLATE 解压（上限 16MB 防炸弹） |

## 主题

浅色蓝紫扁平主题。`Themes/Theme.xaml` 集中定义颜色/画刷、排版、间距及按钮、输入框、表格、Tab 等共享样式，颜色一律 `DynamicResource` 引用，不留硬编码色值——为后期多主题留扩展口。
